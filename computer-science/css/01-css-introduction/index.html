1 Introducing CSS

HTML gives every page its structure and meaning. CSS gives it a visual identity. This chapter establishes the mental model that makes all future CSS knowledge fit together — the invisible-box thinking that everything else in CSS builds on.

1. Big Picture Overview

CSS stands for Cascading Style Sheets. Where HTML describes what content is — headings, paragraphs, links — CSS describes how that content should appear visually. The two languages have deliberately separate responsibilities, and keeping them separate is the foundation of clean, maintainable web design.

The word cascading points to one of CSS's defining behaviours: when multiple rules compete to style the same element, CSS resolves the conflict using a predictable priority order. You do not need to memorise this cascade immediately — but understanding that it exists explains why some styles seem to override others.

The mental model you need to carry into the rest of CSS study is this: every HTML element, regardless of what it is or how small it appears on screen, occupies a rectangular box. CSS controls everything about that box — its size, its colour, its border, its position, and the typography inside it. Once this box model becomes intuitive, CSS stops feeling arbitrary.

What CSS Can Control

CSS can specify rules as concrete as: all <h1> elements appear in blue italics using the Times typeface; all paragraphs use Arial in grey; the page background is cream. The reason CSS feels powerful is that one rule can instantly affect every matching element across the entire page.

2. The Invisible Box Around Every Element

Before writing a single CSS rule, you need one fundamental insight: the browser treats every HTML element as if it lives inside an invisible rectangular box. This is not a metaphor — it is literally how the browser calculates where to place things on screen.

CSS rules do not float freely. They target these boxes. When you write a CSS rule, you are telling the browser: find the boxes that match this description, then apply these visual instructions to them.

Block vs. Inline Elements — Two Kinds of Boxes

Not all boxes behave the same way. The browser distinguishes between two fundamental display modes:

Type Behaviour Common examples
Block-level Each element starts on a new line and stretches the full available width <h1>–<h6>, <p>, <div>
Inline Sits within the flow of text, on the same line as surrounding content <b>, <i>, <img>, <em>, <span>

Block elements create a clean vertical stack — each one breaks to a new line. Inline elements live within the text stream — a <b> tag inside a sentence does not push surrounding words to a new line. Understanding this difference explains why CSS layout behaves the way it does.

Every HTML element — visualised as boxes within boxes

Margin — space outside the border
Border — the visible edge
Padding — space between border and content
Content — text, image, child elements

Why This Matters

CSS rules that affect boxes — like width, height, border, background-color, and position — operate on the outer structure of an element. Rules that affect text inside a box — like color, font-family, and font-size — operate on the content within. Keeping these two categories mentally separate reduces confusion.

3. How CSS Rules Are Written

CSS works by associating rules with HTML elements. A rule tells the browser: for every element that matches this description, apply these visual instructions. Each rule has exactly two parts: a selector and a declaration.

p {
    font-family: Arial;
}
Selector

Which element(s) to target

Property

What aspect to change

Value

What setting to apply

Declaration = Property + Value

The full instruction inside the curly braces

Selectors

The selector sits before the opening curly brace. It identifies which HTML elements the rule applies to. The simplest selectors are element-type selectors — the tag name alone. Writing p as the selector means "apply this rule to every <p> element on the page."

Multiple elements can share the same rule. Separate their names with commas and the declaration applies to all of them: 

/* This single rule targets h1, h2, and h3 simultaneously */
h1, h2, h3 {
    font-family: Arial;
    color: yellow;
}

Declarations

The declaration block sits between the curly braces { }. It contains one or more declarations, each consisting of a property and a value, separated by a colon. Multiple declarations are separated by semicolons. Each declaration expresses one specific styling instruction.

Part Role Examples
Property The aspect of the element you want to change color, font-family, width, border
Value The specific setting you want for that property yellow, Arial, 200px, 2px solid red

Learning CSS is largely a matter of learning available properties and the values they accept. The syntax structure — selector, curly braces, property: value; — stays identical for every rule you will ever write.

4. Categories of CSS Styling

CSS properties fall into two broad categories based on what they control. Keeping these categories in mind helps you reach for the right property when you want a specific effect.

Category What it controls Example properties
Box styling The rectangular container itself width, height, border, background-color, position
Text styling The typography inside the box font-family, font-size, color, font-style, text-transform
Element-specific Rules tailored to particular HTML elements List markers, table borders, form control appearance

When you look at a designed web page, almost every visual decision comes from one of these three categories. The background gradient behind a hero section is box styling. The serif font in an article is text styling. The alternating row colours in a data table are element-specific styling.

5. Three Ways to Apply CSS to a Page

A browser needs to be told where to find the CSS rules for a page. There are three distinct methods, each with different appropriate uses.

Recommended

External Stylesheet

CSS lives in a separate .css file. The HTML page links to it using a <link> element in the <head>. One file can style every page of a site.

Single-page use

Internal (Embedded) CSS

CSS rules are written inside a <style> element within the HTML page's <head>. Affects only that page.

Avoid in new code

Inline Styles

A style attribute placed directly on an HTML element. Affects only that one element. Hard to maintain; appears in legacy code.

External CSS: The <link> Element

When using an external stylesheet, the <link> element carries three essential attributes. Understanding each one clarifies what the browser needs to know:

1
href — the path to the CSS file

Tells the browser where the CSS file is located. Commonly placed in a folder called css or styles for organisation. Follows the same relative/absolute path rules as any link.

↓
2
type — the content type of the linked file

Historically set to text/css to tell the browser what kind of file is being linked. In modern HTML5 this attribute is optional (browsers default to CSS), but you will see it in existing codebases.

↓
3
rel — the relationship between the HTML and the linked file

Set to stylesheet when linking a CSS file. This is the attribute that tells the browser: treat this linked file as the styling source for this page — not as a script, icon, or any other kind of resource.

<!-- External CSS linked in the <head> -->
<head>
    <title>Using External CSS</title>
    <link href="css/styles.css" type="text/css" rel="stylesheet" />
</head>

/* css/styles.css */
body {
    font-family: Arial, Verdana, sans-serif;
    background-color: rgb(185, 179, 175);
}

h1 {
    color: rgb(255, 255, 255);
}

A single HTML page can reference more than one external stylesheet using multiple <link> elements. A common pattern is one stylesheet for typography and colours, and a second for layout — keeping concerns cleanly separated even within CSS itself.

Internal CSS: The <style> Element

When rules are embedded directly in the page, they sit inside a <style type="text/css"> element, placed in the <head>. The syntax of the rules is identical to an external stylesheet — only the delivery mechanism changes. Use this method only when one page genuinely needs rules that no other page will share. 

<head>
    <style type="text/css">
        body {
            font-family: arial;
            background-color: rgb(185, 179, 175);
        }
        h1 {
            color: rgb(255, 255, 255);
        }
    </style>
</head>

6. Why External Stylesheets Are Preferred

For any site with more than one page, the external stylesheet approach is not simply a convention — it is an engineering decision with three concrete benefits. These same benefits are the reason CSS was designed as a separate language rather than being folded into HTML itself.

1
Consistency across all pages

Every page links to the same stylesheet. If you want all headings to become blue, you change one file. Without external CSS, you would have to edit every individual page — a task that scales impossibly with site size.

↓
2
Separation of content from presentation

Your HTML file contains only the content and its structure. Your CSS file contains only the visual rules. Each can be read, edited, and understood independently. This separation is one of the foundational principles of good web architecture.

↓
3
Single-point redesign

When a site's visual identity changes — new brand colours, different typography — the content in every HTML page stays untouched. Only the stylesheet changes. Without this, a visual redesign requires reopening and modifying every HTML file in the project.

7. Important Distinctions

Concept A vs. Concept B Key distinction
Selector vs. Declaration The selector identifies which element; the declaration describes how to style it
Property vs. Value The property names the aspect (e.g. color); the value sets the specific setting (e.g. yellow)
Block element vs. Inline element Block starts on a new line and fills available width; inline flows within the surrounding text
External CSS vs. Internal CSS External lives in a separate .css file shared across pages; internal is embedded per-page in a <style> tag
HTML structure vs. CSS appearance HTML defines what content is; CSS defines how it looks — different questions, different languages

8. Common Misconceptions

❌
"CSS rules apply to individual characters or words."

A CSS rule targets elements — complete HTML tags like <p> or <h1>. To style a single word differently within a paragraph, you must first wrap it in an inline element like <span> and then target that element with CSS.

✓ CSS targets elements (boxes). To target sub-word content, you need an HTML wrapper first.
❌
"The selector and the declaration are interchangeable parts of a rule."

They have completely different jobs and neither can fill the role of the other. The selector is a query — it identifies targets. The declaration is an instruction — it says what to do to those targets. Swapping them produces invalid CSS.

✓ Selector = who. Declaration = what to do. Both are required, non-swappable halves of a rule.
❌
"Inline styles are fine for real projects — they're simpler."

Inline styles feel simpler at first because you see the CSS right next to the HTML it affects. But they cannot be reused, cannot be overridden cleanly, scatter visual rules throughout an HTML file, and make redesigning anything a painstaking manual task. They exist in the language for edge cases only.

✓ Inline styles trade short-term ease for long-term fragility. Use external stylesheets for any real project.
❌
"A declaration is just the value — the property is something else."

A declaration is the complete unit: property + value together, separated by a colon. Neither alone is a declaration. The property is the name of the aspect you want to change; the value is the setting you want for it. Both are required to form one declaration.

✓ Declaration = property: value; — it is always both parts as a pair.
❌
"Block and inline elements look different by default."

The distinction is about layout behaviour, not visual appearance. A block element takes up a full line; an inline element does not. You can make a block element look tiny, and an inline element can be styled to look large. The CSS property display can even switch between the two modes entirely.

✓ Block vs. inline describes how an element flows on the page, not how it looks.

9. Concept Checkpoints

These questions require reasoning — not recall. Work through them before moving to the next chapter.

On the Box Model

  • If every HTML element is a box, what does it mean for an inline element like <b> — is it also a box? How does its box behave differently from a <div>?
  • CSS can control the width and height of a box. Why would those properties behave differently for an inline element versus a block element?

On Rules and Selectors

  • A single rule can target h1, h2, h3 simultaneously. What would break if you forgot the comma between them? What different behaviour would the browser interpret?
  • If the selector determines which elements a rule applies to, what happens when there are zero matching elements on a page — does the rule cause an error?

On CSS Delivery

  • If a site has 50 pages all linking to one external stylesheet, and you change the background colour in that stylesheet, what happens — and why is this architecturally significant?
  • An internal stylesheet and an external stylesheet can both define rules for <h1>. If both are active on the same page, which one takes effect? What principle is this an example of?

10. Chapter-Level Mental Model

This chapter trains a very specific way of seeing web pages. When a browser loads a page, it does not see text, images, and links — it sees a nested hierarchy of boxes. Every element, from the outermost <body> to the most deeply nested <span>, is a box. CSS is the language you use to describe what those boxes look like.

A CSS rule is a precise instruction: "Find all boxes that match this selector, then apply this list of declarations to each one." Every declaration is a property-value pair that addresses one specific visual aspect of a box — its background colour, its typeface, its border, or its position.

The separation between HTML (what boxes exist and what they mean) and CSS (what those boxes look like) is not arbitrary. It enables one stylesheet to control thousands of pages, lets visual redesigns happen without touching content, and allows content to be restyled for print, screen, or accessibility without ever editing the underlying structure.

Carry This Forward

Every CSS property you will ever learn either controls a box's container (size, border, background, position) or controls the typography within it (font, colour, size, style). Every selector you will ever write is simply a more precise or more powerful way of identifying which boxes to target. The rest of CSS is depth, not a different kind of thinking.

Section Summary

In this chapter you learned:

  • CSS is the presentation language of the web — it answers how content looks, while HTML answers what content is
  • The box model: every HTML element occupies a rectangular box; CSS controls that box and the content within it
  • Block-level elements stack vertically; inline elements flow within text — this distinction governs how CSS properties apply
  • A CSS rule = selector + declaration block. A declaration = property: value; — the fundamental unit of styling
  • Commas in selectors (h1, h2, h3) share one rule across multiple element types
  • Three methods of CSS delivery: external (<link>), internal (<style>), inline (style attribute)
  • External stylesheets are architecturally preferred: one file controls all pages; content and presentation stay separate; redesign touches one file only
  • CSS properties divide into box properties (size, border, background, position) and text properties (font, colour, style)
