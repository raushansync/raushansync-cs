1 How the Web & HTML Work

Before you write a single tag, understand what the web actually is — from the cables under the ocean to the pixels on your screen. This is the mental model that makes everything else click.

1. The Internet Is Not the Web

Almost everyone uses these two terms interchangeably, but they are genuinely different things — and confusing them leads to fuzzy thinking about how everything else works.

The Internet is the physical infrastructure: the cables, routers, fibre optic lines running under oceans, wireless towers, and satellites that connect billions of devices together. It is a global network of networks. It was born in the 1960s (ARPANET) and it carries many different things — email, video calls, online gaming, and yes, the web.

The World Wide Web (the web) is one service that runs on top of the internet. It is a system of interlinked documents and resources — web pages — that you access using a browser. The web was invented by Tim Berners-Lee in 1989 as a way to share research documents. It is built on three technologies: URLs, HTTP, and HTML.

Analogy: Roads vs Cars

The internet is the road network — highways, streets, and lanes connecting every city and town. The web is the postal delivery system that uses those roads to carry letters (web pages) from one address (server) to another (your browser). Email is a different delivery company using the same roads. They coexist, but they are separate services.

Concept The Internet The Web
What it is Global physical network of connected devices A system of linked documents accessed via browsers
Born 1960s (ARPANET) 1989 (Tim Berners-Lee, CERN)
Protocol TCP/IP (how data travels) HTTP/HTTPS (how pages are requested)
Examples Email (SMTP), gaming (UDP), video calls Websites, web apps, REST APIs
Analogy The road network The postal delivery service using those roads

2. What HTML Actually Is

HTML stands for HyperText Markup Language. Let's unpack that word by word, because each part matters.

HyperText means text that contains links — text that points to other text. Click a link on Wikipedia and you jump to another page. That linkability, that web of references, is hyper-text. It is the original superpower of the web.

Markup means you annotate plain text with special tags to give it meaning. You wrap words in tags that say "this is a heading", "this is a paragraph", "this is an image". HTML does not describe what things look like — that is CSS's job. HTML describes what things are.

Language — but not a programming language. HTML has no logic, no loops, no conditions, no algorithms. It is a markup language: a set of instructions for describing structure. You will hear people debate whether HTML is "real coding". The answer is: it is a different kind of writing entirely, and it is fundamental.

The One-Sentence Mental Model

HTML is a vocabulary of labels that you wrap around content to tell the browser — and the world — what that content is, not what it looks like.

Here is the most minimal valid HTML page that can exist:

<!-- The simplest possible HTML document -->
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8">
    <title>My First Page</title>
  </head>
  <body>
    <h1>Hello, World!</h1>
    <p>This is a paragraph of text.</p>
  </body>
</html>

Even in these ten lines, every tag has a job. <h1> means "this is the most important heading on the page". <p> means "this is a paragraph". The browser reads those labels and knows — structurally, semantically — what it is dealing with.

3. What Happens When You Type a URL

You type https://cs.raushansync.com/computer-science/html/ and press Enter. Your browser shows a page in under a second. That feels like magic, but it is a very precise sequence of steps. Understanding this sequence will make you a dramatically better developer.

Your Browser
Chrome, Firefox, Safari — the client. Sends requests, renders responses.
asks IP → ← IP address
DNS Server
Translates human-readable domain names into numeric IP addresses.
GET request → ← HTML response
Web Server
Listens for requests. Returns files, runs code, sends back HTML.

Here is that journey, step by step:

1
You type a URL and press Enter

A URL (Uniform Resource Locator) has parts: the protocol (https://), the domain (cs.raushansync.com), and the path (/computer-science/html/). Your browser parses these apart immediately.

↓
2
DNS Lookup — translating the name into an address

Computers speak in IP addresses (like 104.21.42.7), not domain names. DNS (Domain Name System) is the internet's phone book. Your browser asks a DNS server: "What IP address does cs.raushansync.com map to?" The DNS server replies with a number. Your browser caches this for next time.

↓
3
TCP Connection — opening a channel

Your browser establishes a reliable connection to that IP address using TCP (Transmission Control Protocol). Think of it as making a phone call before you start talking. With HTTPS, there is also a TLS handshake here — both sides agree on encryption keys so no one can eavesdrop on the conversation.

↓
4
HTTP Request — the browser asks for a resource

Your browser sends an HTTP GET request across that connection. It is a text message that says something like: "GET /computer-science/html/ HTTP/1.1 — Host: cs.raushansync.com". This is the actual "request" in the request-response cycle.

↓
5
Server Processes & Responds

The web server receives the request, finds the right resource (an HTML file, or the output of some backend code), and sends back an HTTP response. The response has a status code (200 OK, 404 Not Found, 301 Moved) and a body — the actual HTML text.

↓
6
Browser Parses HTML & Requests Sub-resources

As the browser reads the HTML, it discovers more things to fetch — CSS files, JavaScript files, images, fonts. It fires off new requests for each one, often in parallel. This is why the number of network requests matters for page speed.

↓
7
Browser Renders the Page

With HTML, CSS, and JavaScript in hand, the browser builds the page and paints it on screen. You see the result. This whole process — from pressing Enter to pixels on screen — typically takes 200–800 milliseconds on a good connection.

HTTP Status Codes You Will Encounter

Every server response starts with a three-digit code. 200 means success. 301/302 means redirect. 404 means the resource was not found on the server. 500 means the server itself crashed or errored. These codes are part of the HTTP standard — every server and browser in the world understands them.

4. A Deep Look at HTML

Tags, Elements, and Attributes

HTML is built from elements. An element is made of an opening tag, some content, and a closing tag: 

<!-- Anatomy of an HTML element -->
<p class="intro">This is a paragraph.</p>

<!-- Opening tag: <p class="intro"> -->
<!-- Attribute: class="intro" (name="value") -->
<!-- Content: This is a paragraph. -->
<!-- Closing tag: </p> -->

<!-- Some elements are self-closing — they have no content -->
<img src="photo.jpg" alt="A mountain landscape">
<br>
<input type="text" placeholder="Your name">

Attributes live inside the opening tag and add extra information about the element. src on an image tells the browser where the image file lives. href on a link tells it where to navigate. class and id let CSS and JavaScript target specific elements.

The Document Structure — Always the Same Shape

<!DOCTYPE html> <!-- Declares HTML5 document mode -->
<html lang="en"> <!-- Root element; lang helps accessibility and SEO -->

  <head> <!-- Metadata container (not shown in page body) -->
    <meta charset="UTF-8"> <!-- Enables full Unicode text encoding -->
    <meta name="viewport" content="width=device-width, initial-scale=1.0"> <!-- Makes layout responsive on mobile -->
    <title>Page Title</title> <!-- Text shown in browser tab and search results -->
    <link rel="stylesheet" href="style.css"> <!-- Loads external CSS file -->
  </head> <!-- Ends metadata section -->

  <body> <!-- Starts visible page content -->
    <header> <!-- Top area: logo, nav, intro -->
      <nav>...</nav> <!-- Navigation links -->
    </header> <!-- Ends header area -->
    <main> <!-- Main content region of the page -->
      <article> <!-- Self-contained content unit -->
        <h1>Main Heading</h1> <!-- Primary heading for this page/section -->
        <p>Content paragraph...</p> <!-- Regular paragraph text -->
      </article> <!-- Ends article block -->
    </main> <!-- Ends main content region -->
    <footer>...</footer> <!-- Bottom area: copyright/links -->
    <script src="app.js"></script> <!-- Loads JavaScript after HTML content -->
  </body> <!-- Ends visible page content -->

</html> <!-- Ends the HTML document -->

Semantic HTML — Meaning Over Appearance

You could build an entire website using nothing but <div> elements with different classes. It would look identical to a site built with proper semantic HTML. But it would be far inferior in three ways: screen readers could not understand it, search engines would rank it lower, and other developers would find it much harder to maintain.

Semantic HTML means using the tag whose name matches the purpose of the content:

Semantic Tag Meaning Use it for
<header> Introductory content for its nearest section Site header, article header
<nav> A block of navigation links Main menu, breadcrumbs, sidebar links
<main> The primary content of the page Once per page only
<article> Self-contained, independently shareable content Blog posts, news stories, product cards
<section> A thematically grouped part of content Chapters, topic groups within a page
<aside> Content tangentially related to the main content Sidebars, pull quotes, related links
<footer> Closing content for its nearest section Copyright, contact links, sitemaps
<h1>–<h6> Hierarchical headings (1 = most important) Document outline — use in order, do not skip levels
<p> A paragraph of prose Any block of running text
<ul> / <ol> Unordered / Ordered list Items where order doesn't / does matter
<button> A clickable action trigger Actions that do something; never use <div> for this
<a> A hyperlink (anchor) Navigation to another URL; not for actions

The div/span Rule

<div> and <span> are generic, meaningless containers — use them only when no semantic tag fits. <div> is a block-level container for layout grouping. <span> is an inline (stays in the same line) container for styling a piece of text. If there is a semantic alternative, use it.

5. The DOM — HTML Comes Alive

When a browser reads your HTML file, it does not just display it as text. It parses it — reads it carefully, checks for errors, and builds an internal tree-shaped data structure called the Document Object Model, or DOM.

The DOM is a live, in-memory representation of your HTML document. Every element becomes a node in the tree. Parent elements contain child elements. Sibling elements sit next to each other. The browser uses the DOM to render the page, and JavaScript uses the DOM to make the page interactive.

Given this HTML:

<html>
  <head>
    <title>My Page</title>
  </head>
  <body>
    <h1>Welcome</h1>
    <p>Hello, <strong>world</strong>!</p>
  </body>
</html>

The browser builds this DOM tree:

🌐
html Root node — everything lives inside this
├──
🧠
head Metadata branch → child: title → text node: "My Page"
└──
📄
body Visible content branch
├──
📌
h1 Element node → child text node: "Welcome"
└──
📌
p Element node → children: text "Hello, ", element strong → text "world", text "!"
└──
📝
Text Nodes Leaf nodes — actual text content lives here, not in element nodes

The DOM Is Not Your HTML File

The DOM is what the browser builds from your HTML — it is a live object in memory. If JavaScript changes the DOM (adds a button, removes a paragraph), the page updates instantly. But your original HTML file on disk stays unchanged. This is how every interactive website works.

JavaScript can query and manipulate the DOM:

// Find an element by its id
const heading = document.getElementById('main-title');

// Change its text content
heading.textContent = 'Hello from JavaScript!';

// Create a new element and add it to the page
const newPara = document.createElement('p');
newPara.textContent = 'This paragraph was added dynamically.';
document.body.appendChild(newPara);

// Listen for user interaction
document.querySelector('button').addEventListener('click', () => {
    alert('Button clicked!');
});

6. How the Browser Renders a Page

Getting HTML to the browser is only half the story. What the browser does with it is where the real engineering happens. The process is called the Critical Rendering Path.

1
Parse HTML → Build the DOM

The browser's HTML parser reads the raw text, byte by byte, and constructs the DOM tree you saw above. When it encounters a <link> tag pointing to CSS, or a <script> tag, it fires off new network requests to fetch those files.

↓
2
Parse CSS → Build the CSSOM

In parallel (or shortly after), the browser parses all CSS files and builds a second tree: the CSSOM (CSS Object Model). It works out which styles apply to which elements, taking into account specificity, inheritance, and cascade order. The CSSOM is a computed map of "element X gets these exact visual properties".

↓
3
Combine → Build the Render Tree

The browser merges the DOM and CSSOM into a Render Tree. This tree contains only the visible elements (anything with display: none is excluded), each annotated with its computed styles. Hidden elements exist in the DOM but are absent from the render tree.

↓
4
Layout (Reflow)

The browser calculates the exact position and size of every node in the render tree — where does this paragraph start, how wide is this image, how many lines does this text wrap to? This is called layout or reflow. It outputs a box geometry for every element.

↓
5
Paint

The browser converts each element into actual pixels on screen — drawing backgrounds, borders, text, shadows, images. It may split the page into multiple layers to handle animated elements efficiently.

↓
6
Composite

The GPU composites the layers together in the right order and sends the final image to your screen. Smooth animations work by only compositing layers rather than repainting everything — which is why CSS transform and opacity animations are fast and width or top changes are slow.

Why This Matters for You as a Developer

When JavaScript changes a DOM element's size or position, the browser must redo layout and repaint — which is expensive. When it changes only colour or opacity, it can skip straight to compositing — which is cheap. This is why performance-conscious developers reach for CSS transforms for animations, and avoid JavaScript-driven layout changes inside loops.

7. HTML, CSS, and JavaScript — The Three Roles

Every website you have ever visited is built from three technologies working together. They have very distinct jobs, and mixing them up leads to messy, unmaintainable code.

🦴
STRUCTURE

HTML — The Skeleton

Defines what exists and what it is. The raw content and its semantic meaning. A page without CSS or JS still works — it just looks plain.

🎨
PRESENTATION

CSS — The Appearance

Defines what it looks like. Colour, typography, layout, spacing, animation. CSS reads the DOM and applies visual rules. No CSS = unstyled but functional.

⚡
BEHAVIOUR

JavaScript — The Behaviour

Defines what it does. Responds to clicks, fetches data, updates the DOM, stores state. JS is the only one of the three that is an actual programming language.

Here is how they work together in code:

<!-- HTML: defines the structure -->
<button id="like-btn" class="like-button">👍 Like</button>
<span id="count">0</span> likes

/* CSS: controls how it looks */
.like-button {
    background: #3b82f6;
    color: white;
    border: none;
    border-radius: 8px;
    padding: 0.5rem 1rem;
    cursor: pointer;
    transition: transform 0.1s ease;
}

.like-button:hover {
    transform: scale(1.05);
}

// JavaScript: makes it do something
let count = 0;
document.getElementById('like-btn').addEventListener('click', () => {
    count++;
    document.getElementById('count').textContent = count;
});

HTML created the button and the counter. CSS made the button look good and respond on hover. JavaScript tracked the click and updated the number. Each layer did only its own job — this separation is called Separation of Concerns, and it is a core principle of maintainable web development.

8. Common Beginner Misconceptions

These are the most frequent misunderstandings that trip up people learning web development. Read them carefully — correcting a wrong mental model early saves weeks of confusion later.

❌
"HTML is a programming language."

HTML has no logic, no variables, no control flow, no algorithms. It cannot compute anything. It is a markup language — it annotates content with structure and meaning.

✓ HTML is a markup language. JavaScript is the programming language of the web.
❌
"The internet and the web are the same thing."

The internet is global physical infrastructure. The web is one service (websites) that runs on top of that infrastructure, alongside email, gaming, and video calls.

✓ The web runs on the internet, but is not the internet.
❌
"The browser just displays my HTML file."

The browser parses your HTML, builds a DOM, fetches CSS and JS, constructs a render tree, performs layout, and paints pixels. The HTML file is just the starting input — the final output is the result of several complex processes.

✓ The browser transforms HTML through a multi-stage rendering pipeline.
❌
"HTTPS just means the site is secure/trustworthy."

HTTPS means the connection between your browser and the server is encrypted — no one can intercept the data in transit. It says nothing about whether the site itself is honest, safe, or legitimate.

✓ HTTPS encrypts the connection. A phishing site can still use HTTPS.
❌
"A <div> is just as good as a <button>."

A <div> styled to look like a button is not keyboard-navigable by default, not announced correctly by screen readers, and breaks accessibility for millions of users. Semantic HTML is not optional — it is an ethical responsibility.

✓ Use the right semantic element. The visual appearance and the semantic role are different things.
❌
"Changing the DOM changes my HTML file."

The DOM is a live object in the browser's memory. JavaScript modifications to it are temporary and local. When you refresh, the browser re-parses the original HTML file from scratch.

✓ The DOM and the HTML source file are two separate things.
