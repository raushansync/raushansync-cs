Interactive SQL Lab: Advanced Concepts

Apply mathematical set theory to databases, master three-valued logic by handling unknown data, and utilize powerful aggregation techniques like GROUP BY and HAVING.

Your Lab Tasks

The database contains four tables from a tech company's internal system: frontend_devs, backend_devs, hardware_inventory, and regional_sales. Execute your queries below:

  1. Set UNION (Logical OR): Create a master list of all developers across the company. Write a query to combine all columns from frontend_devs and backend_devs. Notice how duplicates (Full-stack developers) are handled by default!
  2. Set INTERSECT (Logical AND): Who are the Full-stack developers? Find the employees who exist in BOTH the frontend_devs and backend_devs tables.
  3. Set EXCEPT (Difference): Find the developers who are strictly specialized in front-end work. Retrieve records present in frontend_devs but NOT in backend_devs.
  4. Handling NULLs: The IT department needs to audit unassigned equipment. Query the hardware_inventory table to select all items where assigned_to is unknown (NULL).
  5. GROUP BY (Aggregation): The finance team wants a summary. Calculate the total revenue for each region using the regional_sales table. You will need SUM() and GROUP BY.
  6. HAVING Clause: Modify your previous grouping query. Filter the aggregated results to show ONLY regions where the total revenue is strictly greater than 100000.

Task 4: Handling NULLs

Hint: Remember, you cannot use = NULL. You must use IS NULL.

SELECT * FROM hardware_inventory 
WHERE assigned_to IS NULL;

Task 5: GROUP BY

SELECT region, SUM(revenue) AS total_revenue 
FROM regional_sales 
GROUP BY region;

Task 6: HAVING Clause

Hint: HAVING is used to filter aggregated data *after* the GROUP BY has occurred.

SELECT region, SUM(revenue) AS total_revenue 
FROM regional_sales 
GROUP BY region 
HAVING SUM(revenue) > 100000;
