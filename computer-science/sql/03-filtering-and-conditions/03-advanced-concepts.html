Advanced SQL Concepts: Sets, NULLs, and Aggregation

Previously, we covered basic query structures, selections, projections, and standard joins. Now, we extend SQL in three powerful directions: treating tables as mathematical sets, gracefully handling missing information with Three-Valued Logic, and summarizing datasets using aggregate functions.

Part 3 Advanced Concepts

1. Set Operations

The core idea here is to temporarily treat our database relations purely as mathematical sets, rather than multisets.

⚠️ The Structural Condition

To perform set operations, the two relations involved must have an identical structure. This means they must have the same number of columns, and corresponding columns must have compatible data types. You cannot union a table of (A, B, C) with a table of (A, B).

1.1 UNION (Logical OR)

The UNION operator combines the result sets of two queries. Conceptually, each subquery gives a table, and UNION combines both while automatically removing duplicates. This is equivalent to the mathematical operation $R \cup S$.

Example: Find all employees who were assigned to a project in Q1 2023 OR Q2 2024.

(SELECT emp_id 
FROM project_assignment 
WHERE quarter = 'Q1' AND fiscal_year = 2023)

UNION

(SELECT emp_id 
FROM project_assignment 
WHERE quarter = 'Q2' AND fiscal_year = 2024);

1.2 INTERSECT (Logical AND)

The INTERSECT operator returns only the tuples (rows) that are common to both query results. Like UNION, it removes duplicates by default. 

(SELECT emp_id 
FROM project_assignment 
WHERE quarter = 'Q1' AND fiscal_year = 2023)

INTERSECT

(SELECT emp_id 
FROM project_assignment 
WHERE quarter = 'Q2' AND fiscal_year = 2024);

This returns only those employees who worked in BOTH of the specified periods.

1.3 EXCEPT (Set Difference)

The EXCEPT operator (equivalent to $R - S$) returns tuples that appear in the first relation but NOT in the second. 

(SELECT emp_id 
FROM project_assignment 
WHERE quarter = 'Q1' AND fiscal_year = 2023)

EXCEPT

(SELECT emp_id 
FROM project_assignment 
WHERE quarter = 'Q2' AND fiscal_year = 2024);

2. Multiset Versions of Set Operations

By default, UNION, INTERSECT, and EXCEPT remove duplicates. If you need to strictly preserve duplicate entries (retaining SQL's natural multiset behavior), you append the keyword ALL.

Operation Result Count Formula (Tuple $t$ occurs $m$ times in $R$, $n$ times in $S$)
UNION ALL $m + n$
INTERSECT ALL $\min(m, n)$
EXCEPT ALL $\max(0, m - n)$

Note: This is pure multiset arithmetic.

3. Using Sets to Find the Maximum (Without Aggregates)

This is a classic and conceptually vital exercise in relational algebra. How do we find the highest value (e.g., maximum salary) without utilizing the built-in MAX() function?

The Strategy:

  1. Step 1: Find salaries that are NOT the highest. If a salary is less than *some other* salary in the table, it is not the maximum.
  2. Step 2: Get a list of all salaries.
  3. Step 3: Subtract the non-highest salaries from the total list. What remains is the maximum.
-- Step 2: All salaries
(SELECT DISTINCT base_salary 
FROM staff)

EXCEPT

-- Step 1: All non-highest salaries (comparing Cartesian Product)
(SELECT DISTINCT T.base_salary 
FROM staff AS T, staff AS S 
WHERE T.base_salary < S.base_salary);

Important Conceptual Difference: Aggregate functions (like MAX()) return a single scalar value. This set-based method returns a table containing a single tuple.

4. NULL Values & Three-Valued Logic

What is NULL?

In SQL, NULL signifies that a value is Unknown OR the Value does not exist (e.g., missing data because a student might not have a passport, or a value simply hasn't been assigned yet).

Crucially, NULL is NOT:

  • The number 0
  • An empty string ('')
  • The boolean value False

Checking for NULL

Because NULL is an unknown state, you cannot use standard equality operators.

❌ Wrong: WHERE salary = NULL (Comparing anything to NULL yields UNKNOWN).
✅ Correct: WHERE salary IS NULL or WHERE salary IS NOT NULL

Arithmetic with NULL

Any arithmetic operation involving a NULL value directly yields NULL. (e.g., 5 + NULL → NULL).

5. Three-Valued Logic (TRUE, FALSE, UNKNOWN)

Because NULL exists, standard boolean logic is insufficient. SQL utilizes Three-Valued Logic. Any standard comparison (>, <, =, <>) involving a NULL evaluates to UNKNOWN.

Logical Operators under Unknown states

Expression Result Shortcut Reason
UNKNOWN OR TRUE TRUE If at least one side is TRUE, OR is TRUE.
UNKNOWN OR FALSE UNKNOWN Depends entirely on what the unknown value actually is.
TRUE AND UNKNOWN UNKNOWN Depends entirely on what the unknown value actually is.
FALSE AND UNKNOWN FALSE If one side is FALSE, AND is strictly FALSE.
NOT UNKNOWN UNKNOWN The inverse of unknown is still unknown.

The WHERE Clause Rule

Extremely Important: If a WHERE predicate evaluates to UNKNOWN, SQL treats it as FALSE for the purpose of row selection. The row will NOT be returned in the result set.

6. Aggregate Functions

Aggregate functions operate on the multiset of a given column and return a single summarizing value. The standard functions are: AVG, MIN, MAX, SUM, and COUNT.

Examples:

-- Example 1: Average Salary in a Specific Department
SELECT AVG(base_salary) 
FROM staff 
WHERE department = 'Engineering';

-- Example 2: Count distinct employees
SELECT COUNT(DISTINCT emp_id) 
FROM project_assignment;

-- Example 3: Count all rows (tuples) in a table
SELECT COUNT(*) 
FROM staff;

7. The GROUP BY Clause

What if we want the average salary not just globally, but per department? Without GROUP BY, applying an aggregate function collapses the entire result set into one global average.

What GROUP BY does:

  1. Partitions the table into logical groups based on the specified attribute(s).
  2. Applies the aggregate function independently to each group.
  3. Returns exactly one row per group.
SELECT department, AVG(base_salary) AS avg_salary
FROM staff
GROUP BY department;

The Strict Grouping Rule

Every attribute present in the SELECT clause that is NOT aggregated must appear in the GROUP BY clause. Failing to do this results in a syntax error because the database wouldn't know which individual row's data to display alongside the collapsed group data.

8. The HAVING Clause & NULLs in Aggregates

The HAVING Clause

The HAVING clause is used exclusively to filter groups, exactly as the WHERE clause is used to filter individual rows.

Example: Find departments where the average base salary is greater than $85,000.

SELECT department, AVG(base_salary)
FROM staff
GROUP BY department
HAVING AVG(base_salary) > 85000;
WHERE Clause HAVING Clause
Works before grouping Works after grouping
Filters individual rows Filters aggregated groups
Cannot use aggregate functions Can use aggregate functions

Order of Execution

When processing a query, the DBMS follows this conceptual order:

  1. WHERE filters the raw rows.
  2. GROUP BY forms the groups from the surviving rows.
  3. HAVING filters those newly created groups.

Rule: NULL Values & Aggregates

All aggregate functions (except for COUNT(*)) completely ignore NULL values. For example, if some salaries are NULL, SUM(salary) simply adds up the numeric ones and ignores the NULLs.

Special Case: If all values being aggregated are NULL, or if the resulting group is completely empty:

  • COUNT(column) returns 0.
  • COUNT(*) returns the number of rows.
  • AVG, SUM, MIN, MAX return NULL.

Final Insight

This module proves that SQL is far more than a simple query language:

  1. It is an applied implementation of formal relational algebra combined with three-valued logic.
  2. The existence of NULL fundamentally alters boolean logic semantics.
  3. Aggregation isn't just math; it is controlled relational grouping mapping multi-row sets to single-row outputs.
  4. Set operations (UNION, INTERSECT, EXCEPT) connect everyday SQL back to its formal mathematical roots.
