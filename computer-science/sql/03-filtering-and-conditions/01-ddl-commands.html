PostgreSQL DDL Commands: CREATE, ALTER, DROP, TRUNCATE

Learn how to design, modify, and destroy database structures. Data Definition Language (DDL) is the foundational vocabulary for setting up the blueprint of your database objects.

Part 1 DDL Commands

1. What is DDL?

DDL (Data Definition Language) is used to define and modify the structure of a database. It works on the schema (structure), not on the individual records or data inside the tables.

The structure defined by DDL includes:

  • Table name
  • Column names
  • Data types
  • Constraints
  • Metadata of database objects

The 5 Main DDL Commands:

  1. CREATE: Builds a new object.
  2. ALTER: Modifies an existing object.
  3. DROP: Deletes an object entirely.
  4. TRUNCATE: Empties an object but keeps its structure.
  5. RENAME: Changes the name of an object.

2. The CREATE Command

The CREATE command is used to build new database objects such as Tables, Databases, Views, and Indexes.

Syntax

CREATE TABLE table_name (
    column_name datatype constraint
);

Example: Creating an Employees Table

CREATE TABLE employees (
    emp_id INT PRIMARY KEY,
    first_name VARCHAR(50),
    last_name VARCHAR(50),
    age INT
);

Important Rules for CREATE:

  • Column name and datatype are mandatory.
  • Constraints (like PRIMARY KEY) are optional.
  • If no constraint is specified, NULL values and duplicate values are allowed by default.

3. The ALTER Command

Used to modify the structure of an existing table without deleting and recreating it. Possible operations include:

  • Add a column
  • Drop a column
  • Modify datatype
  • Add constraints
  • Rename table/column

Add Column

ALTER TABLE table_name ADD column_name datatype;

Example:

ALTER TABLE employees ADD salary NUMERIC(10,2);

Understanding NUMERIC(10,2):

  • Total digits = 10
  • Digits after decimal = 2

Drop Column

ALTER TABLE table_name DROP COLUMN column_name;

Example:

ALTER TABLE employees DROP COLUMN salary;

4. DROP vs. TRUNCATE Commands

Both commands remove data, but they operate very differently on the underlying table structure.

The DROP Command

Deletes a database object permanently. It removes both the Structure and the Data. This action cannot be undone easily.

DROP TABLE table_name;

Example: DROP TABLE employees;

The TRUNCATE Command

Removes all rows from a table, but keeps the structure intact. It is essentially a fast way to empty a table.

TRUNCATE TABLE table_name;

Example: TRUNCATE TABLE employees;

  • Table structure remains.
  • All records are deleted.
  • Much faster than using the DELETE command.
  • You cannot use a WHERE condition with TRUNCATE.

5. The DELETE Command (DML Context)

While technically a DML (Data Manipulation Language) command, DELETE is heavily related to DROP and TRUNCATE. It is used to delete specific rows from a table based on a condition. 

DELETE FROM table_name WHERE condition;

Example:

DELETE FROM student WHERE roll_no = '21F14';

Best Practice: The Primary Key is preferred in the WHERE clause to avoid accidentally deleting multiple rows.

6. Core Differences: DELETE vs TRUNCATE vs DROP

Feature DELETE (DML) TRUNCATE (DDL) DROP (DDL)
Removes Rows Yes (Based on condition) Yes (All rows) Yes (All rows)
Removes Structure No No Yes
WHERE Clause Allowed? Yes No No
Speed Slow Fast Fast
Can Rollback? Yes Usually No No

7. The RENAME Command

Changes the name of an existing table or column.

Syntax

ALTER TABLE old_name RENAME TO new_name;

Example:

ALTER TABLE employees RENAME TO staff;

10. Important Points

  • DDL modifies schema, not individual records.
  • TRUNCATE is faster than DELETE.
  • DROP removes the structure permanently.
  • DELETE supports the WHERE condition for filtering.
  • The Primary Key should be used for safe deletion of records to avoid duplicates being removed.
  • Constraints control data integrity (e.g., PRIMARY KEY, NOT NULL).

11. Common Mistakes to Avoid

  • ❌ Forgetting the WHERE clause in DELETE → accidentally deletes all rows.
  • ❌ Using DROP instead of TRUNCATE when you only wanted to clear the data but keep the table.
  • ❌ Not checking the primary key before executing a deletion.
  • ❌ Confusing ALTER and UPDATE:
    ALTER = Modifies structure (DDL)
    UPDATE = Modifies data/records (DML)
