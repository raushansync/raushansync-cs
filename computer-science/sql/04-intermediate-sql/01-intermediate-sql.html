Intermediate SQL — Nested Subqueries & Data Modification

This is a comprehensive module where we move beyond basic queries. You'll learn how to write queries inside of other queries to solve complex data problems, and then we will shift gears to explore how to safely modify your database records.

4.1 Subqueries & DML

Part 1: What is a Nested Subquery?

A subquery is simply a SELECT statement written inside another SQL statement. Think of it as an inner query whose result is dynamically computed and used by the outer query to finish its job.

The standard SQL query skeleton is:

SELECT A1, A2, ...
FROM r1, r2, ...
WHERE P

A subquery can appear in any of these three primary positions, but with strict constraints:

Position What it replaces Constraint
SELECT An attribute / column Must return exactly one value (a scalar subquery)
FROM A relation (table) Can return any valid table/result set
WHERE Part of the predicate Typically used for set tests or comparisons

Part 2: Subqueries in the WHERE Clause

This is the most common and powerful use of subqueries. The WHERE clause utilizes subqueries for three primary kinds of logic tests.

2.1 Set Membership — IN and NOT IN

Question: Find projects that were active in both Q1 2023 and Q3 2023.

You might think of the INTERSECT operator. But with a subquery, we frame it differently: "Give me Q1 2023 projects whose project_id also appears in the list of Q3 2023 projects."

SELECT DISTINCT project_id
FROM project_timeline
WHERE quarter = 'Q1' AND year = 2023
  AND project_id IN (
      SELECT project_id
      FROM project_timeline
      WHERE quarter = 'Q3' AND year = 2023
  );

The inner query produces a set of project_ids from Q3. The outer query then checks: does each Q1 project_id belong to that set? That is exactly what IN means — set membership.

NOT IN works the same way but inverted. For example, to find projects running in Q1 2023 but not in Q3 2023, you would simply swap IN for NOT IN.

Tuple-Level Set Membership

IN doesn't have to test a single column. You can test an entire row (tuple) against a set of rows. For example, to count distinct employees assigned to roles supervised by manager ID 8055: 

SELECT COUNT(DISTINCT emp_id)
FROM assignment
WHERE (project_id, role_id, dept_id) IN (
    SELECT project_id, role_id, dept_id
    FROM supervision
    WHERE manager_id = 8055
);

Here you are checking whether a 3-column tuple from assignment exists in the 3-column result set of the subquery.

2.2 Set Comparison — SOME and ALL

These concepts come straight from predicate logic ($\exists$ and $\forall$). Pay close attention to how they evaluate.

SOME (Existential Quantification — $\exists$)

SOME means "at least one." An expression like V > SOME (subquery) evaluates to TRUE if V is greater than at least one value in the subquery's result set. (Note: In SQL, ANY is synonymous with SOME).

Question: Find employees whose salary is greater than that of at least one employee in the 'HR' department.

SELECT emp_name
FROM employee
WHERE salary > SOME (
    SELECT salary
    FROM employee
    WHERE dept_name = 'HR'
);

Mental model: The subquery produces a list of HR salaries (e.g., {40000, 50000, 60000}). For each employee in the outer query, the condition is satisfied if their salary beats even one of those numbers.

Quick Truth-Table Examples with the set {4, 5, 8}:

  • 6 < SOME {4, 5, 8} → TRUE (because 6 < 8)
  • 6 < SOME {6, 7, 8} → TRUE (because 6 < 7)
  • 6 = SOME {4, 6, 8} → TRUE (because 6 = 6)
  • 6 > SOME {7, 8, 9} → FALSE (6 is not greater than any of them)

Important equivalence: = SOME is exactly the same as IN. However, <> SOME is not the same as NOT IN.

ALL (Universal Quantification — $\forall$)

ALL means "every single one." An expression like V > ALL (subquery) evaluates to TRUE only if V is greater than every value in the subquery result.

Question: Find employees whose salary is greater than every single employee in the 'HR' department.

SELECT emp_name
FROM employee
WHERE salary > ALL (
    SELECT salary
    FROM employee
    WHERE dept_name = 'HR'
);

Quick Truth-Table Examples with the set {4, 8}:

  • 6 < ALL {4, 8} → FALSE (6 is not less than 4)
  • 6 < ALL {7, 8} → TRUE (6 is less than both 7 and 8)
  • 6 <> ALL {4, 8} → TRUE (6 is not equal to 4, and not equal to 8)

Important equivalence: <> ALL is exactly the same as NOT IN. However, = ALL is not the same as IN.

2.3 Test for Empty Relations — EXISTS and NOT EXISTS

EXISTS (subquery) returns TRUE if the subquery produces at least one row. It returns FALSE if the result set is completely empty. Conversely, NOT EXISTS returns TRUE only when the subquery result is empty.

Question: Find all projects active in both Q1 2023 and Q3 2023 (using EXISTS).

SELECT project_id
FROM project_timeline AS PT1
WHERE quarter = 'Q1' AND year = 2023
  AND EXISTS (
      SELECT *
      FROM project_timeline AS PT2
      WHERE quarter = 'Q3' AND year = 2023
        AND PT1.project_id = PT2.project_id
  );

Correlated Subqueries

Notice in the example above, the inner query references PT1.project_id from the outer query. This is called a correlated subquery. Unlike a standard subquery that runs once, a correlated subquery is re-evaluated for each individual row processed by the outer query. The alias PT1 acts as the correlation name.

NOT EXISTS — A Powerful Mathematical Trick

SQL does not have a direct logical operator for "for all" relations (e.g., checking if one entire set encompasses another). We simulate it using NOT EXISTS based on a fundamental mathematical insight from set theory:

$X - Y = \emptyset \iff X \subseteq Y$

In plain English: "The set of IT Projects minus the projects this employee has worked on is empty" means exactly "This employee has worked on all IT Projects."

Question: Find all employees who have worked on every project offered by the IT department.

SELECT DISTINCT E.emp_id, E.emp_name
FROM employee AS E
WHERE NOT EXISTS (
    SELECT project_id FROM project WHERE dept_name = 'IT'
    EXCEPT
    SELECT A.project_id FROM assignment AS A WHERE E.emp_id = A.emp_id
);

Read this as: "Find employees for whom there is no IT project that they haven't worked on." The inner EXCEPT calculates (All IT Projects) minus (Projects this employee worked on). If that difference is empty (NOT EXISTS), the employee worked on all of them.

2.4 Test for Duplicate Tuples — UNIQUE

The UNIQUE(subquery) construct returns TRUE if there are no duplicate rows in the subquery's result.

Question: Find all projects that were offered at most once in 2023.

SELECT P.project_id
FROM project AS P
WHERE UNIQUE (
    SELECT T.project_id
    FROM project_timeline AS T
    WHERE P.project_id = T.project_id AND T.year = 2023
);

If a project appears twice in the timeline for 2023, the subquery generates duplicates → UNIQUE returns FALSE → that project is excluded. If it appears zero or one time, it returns TRUE.
⚠️ Note: UNIQUE is part of the SQL standard, but support varies by DBMS. In PostgreSQL, you would typically use COUNT(*) <= 1 instead.

Part 3: Subqueries in the FROM Clause

Since a query always returns a relation (a table), you can take the result of any query and use it as if it were an actual table inside the FROM clause. This is commonly called a derived table or inline view.

Question: Find departments where the average employee salary exceeds $90,000.

SELECT dept_name, avg_salary
FROM (
    SELECT dept_name, AVG(salary) AS avg_salary
    FROM employee
    GROUP BY dept_name
) AS dept_avg
WHERE avg_salary > 90000;

The inner query computes a temporary table with two columns: dept_name and avg_salary. The outer query then treats this exactly like a real table and filters it using a standard WHERE clause. Notice we didn't need a HAVING clause here—the subquery handled the aggregation, and the outer query handled the filtering.

Part 4: The WITH Clause (Common Table Expressions)

The WITH clause allows you to define a named temporary relation before your main query begins. It makes code significantly cleaner than deeply nesting subqueries in the FROM clause, especially when you need to reference the same derived table multiple times.

Question: Find all departments that have the maximum budget in the company.

WITH max_budget(value) AS (
    SELECT MAX(budget) FROM department
)
SELECT department.dept_name
FROM department, max_budget
WHERE department.budget = max_budget.value;

More complex example: You can chain these temporary tables together. Let's find departments where the total payroll exceeds the average total payroll across all departments.

WITH dept_payroll(dept_name, total) AS (
    SELECT dept_name, SUM(salary)
    FROM employee
    GROUP BY dept_name
),
avg_payroll(value) AS (
    SELECT AVG(total) FROM dept_payroll
)
SELECT dept_name
FROM dept_payroll, avg_payroll
WHERE dept_payroll.total > avg_payroll.value;

Notice how the second WITH statement (avg_payroll) queries directly from the first one (dept_payroll). This chaining is what makes WITH an incredibly powerful tool for readable SQL.

Part 5: Subqueries in the SELECT Clause (Scalar)

When a subquery appears in the SELECT clause, it must be guaranteed to return exactly one value (one row, one column). If it returns multiple rows, the database will throw a runtime error.

Question: List all departments alongside the total count of employees working in each.

SELECT dept_name,
       (
           SELECT COUNT(*)
           FROM employee
           WHERE department.dept_name = employee.dept_name
       ) AS num_employees
FROM department;

For every department row processed, the correlated subquery counts the matching employees and returns that single number to populate the num_employees column.

Part 6: Modifications of the Database

Up to this point, we have only read data (Querying). Now we shift to DML (Data Manipulation Language) to change the data itself. There are three operations: DELETE, INSERT, and UPDATE.

6.1 DELETE

The syntax removes entire rows that match a condition.

DELETE FROM relation WHERE condition;
  • Delete all rows: DELETE FROM employee; (Warning: empties the table but keeps the structure).
  • Simple condition: DELETE FROM employee WHERE dept_name = 'Finance';

Delete using a subquery:

DELETE FROM employee
WHERE dept_name IN (
    SELECT dept_name 
    FROM department 
    WHERE building = 'North Wing'
);

⚠️ A Critical Trap: Deleting based on Aggregates

DELETE FROM employee
WHERE salary < (SELECT AVG(salary) FROM employee);

The Conceptual Problem: As you delete the lowest-paid employees one by one, the average salary changes. Would subsequent deletions use a new, higher average?

The Solution: SQL prevents this bug. It evaluates the subquery completely first, identifies all target rows based on that static average, and then deletes them all at once. Be aware of this pattern, as other programming languages might bite you with "stale" data loops.

6.2 INSERT

Insert adds new tuples into a table.

Insert a single tuple positionally (values must exactly match table column order):

INSERT INTO project
VALUES ('PRJ-99', 'Cloud Migration', 'IT', 150000);

Insert with explicit columns (safer, order-independent):

INSERT INTO project (proj_name, dept_name, proj_id, budget)
VALUES ('Cloud Migration', 'IT', 'PRJ-99', 150000);

Bulk Insert using a SELECT query:

Let's say we want to create a new record in a benefits table for every single employee currently in the system.

INSERT INTO benefits (emp_id, tier, vacation_days)
SELECT emp_id, 'Standard', 15
FROM employee;

Important: The SELECT query is fully evaluated before any insertions happen, preventing infinite loops if you are inserting into the same table you are querying from.

6.3 UPDATE

Update modifies the values of existing columns in existing rows.

UPDATE relation
SET attribute = new_value
WHERE condition;

The Order-of-Operations Bug

Imagine we need to give a 3% raise to employees earning over $80,000, and a 5% raise to everyone else. A naive approach uses two statements:

UPDATE employee SET salary = salary * 1.03 WHERE salary > 80000;
UPDATE employee SET salary = salary * 1.05 WHERE salary <= 80000;

The trap: If someone earns $ 79,000 , the first statement ignores them. The second statement runs, bumping them by 5% to $82,950. But what if we ran them in reverse? Someone earning exactly $80,000 would get the 5% raise (becoming $84,000), and then also get the 3% raise on the next line because they now satisfy the > 80000 condition!

The clean solution is the CASE statement, which handles branches atomically in one pass:

UPDATE employee
SET salary = CASE
    WHEN salary <= 80000 THEN salary * 1.05
    ELSE salary * 1.03
END;

CASE evaluates the condition for each row once, applies exactly one branch, and never double-applies logic.

Update using a Scalar Subquery:

You can dynamically pull data from other tables to run an update. Here, we update a summary column total_projects on the employee table based on a live count from the assignments table.

UPDATE employee E
SET total_projects = (
    SELECT COUNT(*)
    FROM assignment A
    WHERE E.emp_id = A.emp_id
);

Summary of Key Concepts

Concept What it does
IN / NOT IN Set membership test
SOME $\exists$ — true if condition holds for at least one tuple
ALL $\forall$ — true only if condition holds for every tuple
EXISTS True if subquery returns any rows
NOT EXISTS True if subquery returns no rows
UNIQUE True if subquery has no duplicate rows
FROM subquery Treat query result as a temporary table
WITH clause Named temporary relations, chainable
Scalar subquery Returns exactly one value, usable in SELECT or UPDATE
DELETE Remove rows matching a condition
INSERT Add rows, individually or via SELECT batch
UPDATE ... SET ... CASE Modify rows, use CASE to avoid procedural ordering bugs
