PostgreSQL Foundations

Before you write a single query, build the mental model that makes everything else click — what PostgreSQL is, how it organises data, and how to get your environment ready.

Part 1 of 13 PostgreSQL Foundations

1. What Is a Database?

A database is an organised collection of data that can be stored, retrieved, and modified in a controlled way. The word "organised" is the important part — it means data lives in a predictable structure, not scattered across files or spreadsheets.

Think of a database as the difference between a pile of paper receipts thrown in a drawer versus those same receipts filed by month, vendor, and amount in a cabinet with labelled folders. Both hold the same information; only one lets you find anything quickly.

Real-World Analogy

A library catalogue is a database. Every book has a record: title, author, ISBN, shelf location. The catalogue lets you ask — "show me all books by Tolkien published after 1950" — and get an instant answer. PostgreSQL is the engine that handles requests like that, but for any kind of data you define.

Why Not Just Use Spreadsheets?

Spreadsheets like Excel or Google Sheets are great for small, manual work. Databases are built for:

Concern Spreadsheet Database (PostgreSQL)
Scale Slows down past ~100k rows Handles billions of rows efficiently
Multiple users Conflicts when two people edit Concurrent access with transaction safety
Relationships Manually duplicated data across sheets Foreign keys link tables automatically
Data integrity Anyone can type anything anywhere Constraints enforce what is allowed
Querying Formulas that break easily SQL — a powerful, declarative language
Automation Requires manual intervention Applications read/write programmatically

2. What Is PostgreSQL?

PostgreSQL (often called Postgres) is a free, open-source relational database management system (RDBMS). It stores data in tables made of rows and columns, and you talk to it using SQL — Structured Query Language.

PostgreSQL has been in active development since 1986, making it one of the most mature and battle-tested database systems in existence. It is used by companies like Instagram, Spotify, GitHub, and Apple — often handling millions of queries per day.

Key Characteristics of PostgreSQL

  • Relational: Data lives in structured tables with defined relationships between them.
  • ACID-compliant: Every transaction is Atomic, Consistent, Isolated, and Durable — your data won't get corrupted even if the power goes out mid-write.
  • Extensible: You can add custom data types, functions, and even programming languages (Python, JavaScript, etc.) directly inside Postgres.
  • Standards-compliant: Postgres follows the SQL standard closely, with useful extensions on top.
  • Open source: Free to use, deploy, and modify under the PostgreSQL licence.

PostgreSQL vs Other Databases

Database Type Key difference from Postgres
MySQL / MariaDB Relational Simpler feature set; Postgres has richer types, better standards compliance, and stronger write-safety defaults
SQLite Relational Embedded, file-based; great for local apps but not designed for multiple concurrent users
MongoDB Document (NoSQL) Stores JSON-like documents, no fixed schema; Postgres can also store JSON natively, so the trade-off is narrower than it seems
Oracle / SQL Server Relational Enterprise, commercial, expensive; Postgres matches or exceeds them for most use cases at zero cost

Why Learn PostgreSQL Specifically?

SQL concepts transfer across almost every relational database. But Postgres is worth learning directly because it has the richest feature set for free, the most active community, and it is the default choice for modern backends. Skills you build here are immediately employable.

3. How PostgreSQL Organises Data

Understanding the hierarchy of objects inside PostgreSQL will save you a lot of confusion later. Here is the structure from largest to smallest:

🖥️
PostgreSQL Server (Cluster) One running PostgreSQL installation on a machine
└──
🗄️
Database A named container — e.g. ecommerce_db, analytics
└──
📂
Schema A namespace inside a database — default is public
└──
📋
Table Named grid of rows and columns — e.g. users, orders
└──
➡️
Row (Record / Tuple) One entry in the table — e.g. a single user
└──
📌
Column (Field / Attribute) A named, typed piece of data — e.g. email TEXT

Tables, Rows, and Columns — Concretely

Every table has a fixed set of columns, each with a specific data type (text, number, date, etc.). Every row is one record that fills in values for each column.

Here is what a users table might look like:

id name email created_at is_active
1 Priya Sharma priya@example.com 2024-01-15 true
2 Arjun Mehta arjun@example.com 2024-02-03 true
3 Sara Nair sara@example.com 2024-03-11 false

Each column has a data type enforced by Postgres. id is an integer, name and email are text, created_at is a date, and is_active is a boolean. You cannot put text into id — Postgres will reject it.

What Is a Schema?

A schema is a namespace — a way of grouping related tables inside one database. By default, all your tables go into the public schema. You can create others (e.g. sales, analytics) to organise large projects and control permissions.

For now, you never need to think about schemas explicitly. Every table you create goes into public automatically, and every query you write can find it there.

4. The Client–Server Architecture

PostgreSQL runs as a server process — a program that sits in the background, listening for incoming connections. You, the developer, connect to it using a client.

Client
psql (terminal) Your Python app DBeaver / pgAdmin Node.js backend
SQL query → ← Result rows
PostgreSQL Server
Parser Query Planner Executor Storage Engine

The client sends a SQL query as text. The server parses it, plans the most efficient way to execute it, runs it, and sends back the results. The client displays them.

This matters because psql — the command-line client we use in this course — is not PostgreSQL itself. It is a tool that talks to the PostgreSQL server. The server is the database; psql is just one way to talk to it.

Analogy: Restaurant

The PostgreSQL server is the kitchen. psql is a waiter. You speak to the waiter (psql), who passes your order (SQL) to the kitchen (Postgres), which prepares the result and hands it back. The kitchen does the actual work; the waiter just carries the messages.

5. Installing PostgreSQL

The official PostgreSQL website at postgresql.org has installers for every major operating system. Here is the fastest path for each platform:

The easiest way on macOS is via Homebrew:

# Install Homebrew first if you don't have it:
# /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

brew install postgresql@16

# Start the PostgreSQL service
brew services start postgresql@16

# Connect using psql
psql postgres

Alternatively, download the Postgres.app from postgresapp.com — a one-click install that puts everything in your Applications folder. 

# Update package list
sudo apt update

# Install PostgreSQL
sudo apt install postgresql postgresql-contrib

# Start the service
sudo systemctl start postgresql
sudo systemctl enable postgresql

# Switch to the postgres user and open psql
sudo -u postgres psql

Download the graphical installer from postgresql.org/download/windows. Run the installer, set a password for the postgres superuser, and keep the default port 5432.

The installer also includes pgAdmin 4 — a graphical interface if you prefer not to use the command line immediately. After installation, search for SQL Shell (psql) in your Start menu to launch it.

On Windows you can also use WSL2 (Windows Subsystem for Linux) and follow the Linux instructions above. This gives you a much nicer terminal experience and is recommended for serious development.

Verifying the Installation

After installation, run this in your terminal to confirm Postgres is running:

psql --version
# psql (PostgreSQL) 16.x

Common Trouble: Port Already in Use

If you see an error like "could not connect to server" or "port 5432 already in use", another Postgres instance may already be running. On macOS/Linux run pg_lsclusters (Linux) or check Postgres.app (macOS). On Windows, check Services in Task Manager.

6. Using psql — Your Command-Line Interface

psql is the official command-line client for PostgreSQL. You type SQL directly into it and see results immediately. It is the best way to learn because there is no abstraction between you and the database.

Connecting to a Database

# Connect to the default 'postgres' database as user 'postgres'
psql -U postgres -d postgres
# Note: If you omit -U, PostgreSQL tries to use your system username as the database user.

# Connect to a specific database
psql -d my_database
# This works only if your system username exists as a PostgreSQL user.
# -d specifies the database name
# -U specifies the username

# Connect as a specific user
psql -U postgres -d my_database

# Full connection string
psql "postgresql://username@localhost:5432/my_database"
# You will be prompted for the password securely.

Once connected, you will see a prompt like this:

psql (16.2)
Type "help" for help.

postgres=#

Note: You may see additional warnings (especially on Windows). This is normal and can be ignored if you see the `postgres=#` prompt.

The # means you are connected as a superuser. A regular user sees => instead. The word before the prompt (postgres) is the name of the database you are connected to.

Essential psql Meta-Commands

psql has special commands that start with a backslash \. These are not SQL — they are instructions to the psql client itself.

Command What it does
\l or \list List all databases on this server
\c dbname Connect (switch) to a different database
\dt List all tables in the current database (current schema)
\d tablename Describe a table — show its columns and data types
\dn List all schemas in the current database
\du List all roles (users) on the server
\timing Toggle query execution time display
\e Open the last query in your system text editor
\i filename.sql Run all SQL from a file
\q Quit psql
\? Show all psql meta-commands
\h SELECT Show SQL syntax help for a command

Try This Right Now

Open psql and type these commands one at a time:

\l           -- see all databases
\c postgres  -- connect to the postgres database
\dt          -- list tables (probably empty at first)
\q           -- quit

Writing SQL in psql

To run a SQL statement, type it and press Enter after the semicolon ;. The semicolon tells Postgres the statement is complete. Without it, pressing Enter just moves to the next line — psql is waiting for you to finish. 

postgres=# SELECT 1 + 1;
 ?column?
----------
        2
(1 row)

Stuck on a Multi-Line Prompt?

If your prompt shows -# or -> instead of =# or =>, psql is waiting for a semicolon. Type ; and press Enter, or press Ctrl + C to cancel the current input and start fresh.

7. Creating Your First Database

You can create a database either from the terminal or from inside psql. Both do the same thing. 

-- From inside psql:
CREATE DATABASE learning_sql;

-- Then connect to it:
\c learning_sql

-- Or from the terminal (outside psql):
createdb learning_sql

To remove a database (be careful — this is permanent): 

DROP DATABASE learning_sql;

For the rest of this course, create a database called learning_sql and keep all your practice tables there. It keeps your work isolated from any system databases.

8. How PostgreSQL Processes a Query

When you send a SQL statement to PostgreSQL, it does not execute it blindly. It goes through a careful pipeline. Understanding this at a high level will help you interpret errors and performance later.

1
Parse

Postgres reads your SQL text and checks the syntax. If you mistype SELCT instead of SELECT, the error comes from here.

↓
2
Analyse / Rewrite

Postgres checks that all table names, column names, and types actually exist. References to undefined tables fail here.

↓
3
Plan

The query planner considers multiple ways to execute your query and picks the fastest one based on table statistics. This is where indexes matter.

↓
4
Execute

The executor actually reads the data from disk (or cache), applies filters, joins tables, and builds the result set.

↓
5
Return

Results are sent back to the client. psql formats them into the table you see on screen.

The Key Insight

SQL is declarative — you describe what you want, not how to get it. The query planner decides how. This is fundamentally different from writing a for-loop in Python. You say "give me all users older than 30" and Postgres figures out the most efficient way to retrieve them.

9. ACID — The Guarantee That Postgres Gives You

When applications write data, things can go wrong — power failures, network drops, simultaneous writes. PostgreSQL protects you through a set of guarantees called ACID:

A
Atomicity

A transaction either completes entirely or not at all. If you transfer money between accounts and the power cuts mid-way, neither account is changed.

C
Consistency

Every transaction brings the database from one valid state to another. Constraints (e.g. "email must be unique") are always enforced.

I
Isolation

Concurrent transactions do not interfere with each other. Two users updating the same row don't overwrite each other's changes silently.

D
Durability

Once a transaction is committed, it is saved permanently — even if the server crashes a millisecond later.

You do not need to implement any of this yourself. Postgres handles ACID automatically for every query you run. It is one of the primary reasons Postgres is trusted for financial, medical, and critical production systems.

10. A First Look at PostgreSQL Data Types

Every column in a Postgres table has a data type. The type determines what values are allowed and how Postgres stores and compares them. You will study types in depth in a later section, but here is the vocabulary you will see immediately:

Category Common Types Example Values
Text TEXT, VARCHAR(n), CHAR(n) 'hello', 'raushan@example.com'
Integer INTEGER, BIGINT, SMALLINT 42, -7, 1000000
Decimal NUMERIC, REAL, DOUBLE PRECISION 3.14, 99.99
Boolean BOOLEAN true, false
Date & Time DATE, TIMESTAMP, TIMESTAMPTZ '2024-06-01', '2024-06-01 14:30:00+05:30'
Auto-increment SERIAL, BIGSERIAL Automatically assigned: 1, 2, 3…
Unique ID UUID 'a0eebc99-9c0b-4ef8-bb6d-6bb9bd380a11'
Missing value NULL Represents the absence of any value

NULL Is Not Zero or Empty String

NULL means unknown or absent. It is not the number zero and not an empty string ''. This distinction causes many beginner bugs. Postgres treats NULL specially — any comparison with NULL returns NULL (not true or false), which is why you use IS NULL rather than = NULL. You will see this in the Filtering section.
